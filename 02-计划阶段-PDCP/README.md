# 02. 计划阶段（PDCP）

> 把概念转化为可执行的项目计划，完成需求/架构基线和预算/资源承诺，通过 PDCP 签署项目任务书。

## 0. 一图看懂

```mermaid
flowchart LR
    A["需求/架构基线"] --> B["WBS/进度/预算"]
    B --> C{"TR1 预审"}
    C -->|通过| D{"PDCP"}
    D -->|Go| E["进入开发"]
    D -->|Rework| B
    D -->|No-Go| F["调整/终止"]
```

## 1. 阶段门禁

- **门禁**：PDCP（商业决策）+ TR1 准入预审
- **准入**：CDCP Go、立项申请书/商业论证获批、PDT 核心团队到位、初始需求/概念方案基线、预算框架预沟通。
- **准出**：需求/架构基线冻结、计划闭合、预算/资源获批、供应/制造/服务可行、Top 风险有应对、任务书签署。

## 2. 重点抓什么

**本阶段重点**：需求基线与架构、WBS/进度/资源/预算、质量/测试计划、供应/制造/服务计划、变更/风险/配置机制

| 必须抓住 | 容易漏掉 | 失败信号 |
|---|---|---|
| ✅ 需求/架构冻结<br>✅ 计划闭合<br>✅ 预算/资源获批<br>✅ 供应/制造/服务可行<br>✅ Top 风险有应对 | ⚠️ WBS 漏项<br>⚠️ 资源只写部门不写人<br>⚠️ 关键路径没有缓冲 | 🚨 计划反复改基线<br>🚨 预算/资源缺口靠“后面再说”<br>🚨 供应/制造未介入 |
